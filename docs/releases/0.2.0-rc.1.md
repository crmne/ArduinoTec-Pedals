# ArduinoTec-Pedals 0.2.0-rc.1

First release candidate for the new calibration firmware and setup experience.

**For hardware testing: physical pedal operation, USB enumeration, game compatibility and end-to-end latency have not yet been validated.**

## Download and install

Download **pedals-0.2.0-rc.1.zip** for the firmware, setup tool and guides. Choose the HEX matching your board: Leonardo, Micro, or Pro Micro **5 V / 16 MHz**.

Follow the included README and prebuilt installation guide. The source archive includes the firmware, tests, tools, libraries and board-core sources. SHA256SUMS covers the downloadable assets.

## Changes

- Guided calibration for released positions, full travel and desired maximum brake pressure, with automatic sensor direction detection and deadzones.
- Calibration saved in two EEPROM slots with integrity checks and recovery from interrupted saves; temporary brake tare does not write EEPROM.
- Correct pedal release reporting, retained brake samples between conversions, and neutral brake output for stale or invalid readings.
- One complete USB report per interval, targeting 1,000 reports/second, with serial diagnostics for observed firmware sampling/submission rates.
- Pinned builds for three boards, automated regression tests, downloadable packages and installation, wiring, calibration and performance guides.

## Upgrading and limitations

**Run calibration after installing this firmware for the first time.** Outputs remain neutral until valid calibration is saved. Close games during setup; outputs resume after save, cancel or session expiry. Existing game bindings may need to be cleared and rebound because the USB device type is now joystick. Axis usages remain throttle, brake and Rx for clutch.

Default images expect three pedals. The old sensitivity potentiometer is disabled by default; saved brake calibration sets maximum pressure. Two-pedal builds, custom wiring and optional potentiometer support require a source build.

The HX711 still supplies only 10 or 80 fresh brake conversions per second, selected in hardware. The 1,000 Hz report target is not a measured sensor rate or latency guarantee. Hall inputs retain the ATmega32u4's 10-bit ADC limits.

Software validation covers simulated firmware behavior, EEPROM interruption, the setup tool talking to a compiled firmware simulator, and builds for all three board profiles.

Before driving, verify released/full travel, persistence across power cycles, brake fault recovery, noise and game bindings on your actual hardware. Include board, sensor, HX711 rate, OS and firmware version in any test report.
